# Sponge-Clone для iOS: Полное руководство и ТЗ для ИИ-агента

Этот файл состоит из двух частей:
1. **Руководство для вас** — как правильно запустить ИИ-агента, собрать приложение (даже если у вас Windows/Linux и нет Mac) и установить его на свой iPhone.
2. **Техническое задание (Промпт) для ИИ-агента** — полная инженерная спецификация для разработки нативного iOS-приложения на SwiftUI + PhotoKit + SwiftData.

# ЧАСТЬ 1. Инструкция для владельца (как всё запустить)

## Шаг 1. Подготовка папки и запуск ИИ-агента
1. Создайте пустую папку на компьютере, например `SwipeClean-iOS`.
2. Положите этот файл внутрь папки (например, под именем `SPEC.md`).
3. Откройте папку в вашем инструменте с ИИ-агентом (**Cursor**, **Claude Code**, **Windsurf**, **Cline** и др.).
4. Напишите агенту короткое сообщение:
   > Прочитай файл `SPEC.md` (Часть 2 — Техническое задание для ИИ-агента). Строго следуй всем правилам и архитектуре. Начни с Фазы 1 и остановись после её завершения для проверки, затем переходи к следующей фазе по моей команде.

> **Важная фишка этого ТЗ:** ИИ-агенты часто ломают внутренний файл проекта Xcode (`.xcodeproj/project.pbxproj`). Поэтому в спецификации ниже заложено использование **XcodeGen (`project.yml`)**. Агент напишет только чистый код на Swift и простой файл `project.yml`, а сам проект Xcode сгенерируется автоматически одной командой — без ошибок и битых ссылок.

## Шаг 2. Как собрать готовое приложение

### Вариант А: Если у вас есть Mac
1. Установите **Xcode** из App Store.
2. Установите **XcodeGen** через терминал (если установлен Homebrew):
   ```bash
   brew install xcodegen
   ```
3. В терминале перейдите в папку проекта и сгенерируйте проект Xcode:
   ```bash
   xcodegen generate
   ```
4. Откройте появившийся файл `SwipeClean.xcodeproj` в Xcode.
5. Выберите свой Apple ID в разделе **Signing & Capabilities -> Team** (можно бесплатный аккаунт).
6. Подключите iPhone по кабелю, выберите его вверху Xcode и нажмите **Play (⌘R)**.
7. На iPhone перейдите в *Настройки -> Основные -> VPN и управление устройством* и нажмите «Доверять» своему Apple ID.

### Вариант Б: Если у вас Windows или Linux (без Mac)
В ТЗ ниже агент автоматически создаст файл `.github/workflows/build-ios.yml`. Он заставит бесплатные облачные серверы Apple/macOS внутри GitHub скомпилировать ваш код в готовый установочный файл `.ipa`.

1. Создайте **приватный** репозиторий на GitHub и загрузите туда код, который написал агент:
   ```bash
   git init
   git add .
   git commit -m "Initial build"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/swipe-clean-ios.git
   git push -u origin main
   ```
2. Перейдите в репозитории на вкладку **Actions**.
3. Вы увидите запущенный процесс **Build Unsigned iOS IPA**. Подождите ~5–8 минут.
4. Когда сборка завершится зеленой галочкой, зайдите внутрь неё и в самом низу в разделе **Artifacts** скачайте архив `SwipeClean-unsigned-ipa` (внутри будет файл `SwipeClean.ipa`).
   * *Если сборка упала с красной ошибкой:* скопируйте текст ошибки из лога GitHub Actions и отправьте своему ИИ-агенту со словами «Исправь ошибку компиляции из лога Xcode», после чего снова сделайте `git push`.

## Шаг 3. Как установить `.ipa` на iPhone (без Mac)

Для установки собственного `.ipa` на iPhone с Windows/Linux используйте один из бесплатных инструментов подписи:

* **Самый простой способ для теста — Sideloadly (Windows / macOS):**
  1. Установите iTunes (не из Microsoft Store, а классическую версию с сайта Apple) и iCloud на Windows.
  2. Скачайте **Sideloadly**, подключите iPhone по кабелю.
  3. Перетащите файл `SwipeClean.ipa` в окно Sideloadly, введите свой Apple ID и нажмите **Start**.
  4. На iPhone: *Настройки -> Конфиденциальность и безопасность -> Режим разработчика (включить)* и *Настройки -> Основные -> VPN и управление устройством -> Доверять*.
  * *Нюанс:* бесплатная подпись действует 7 дней, затем нужно переподписать (данные и прогресс чистки не пропадают).
* **Самый удобный способ на постоянку — SideStore:**
  1. Один раз устанавливается на iPhone с ПК, после чего умеет **автоматически продлевать 7-дневную подпись по Wi-Fi** прямо с телефона без подключения к компьютеру.
  2. Просто отправьте файл `SwipeClean.ipa` себе на iPhone (в «Файлы») и откройте его через SideStore.

# ЧАСТЬ 2. Техническое задание (Промпт) для ИИ-агента

> **Инструкция для ИИ-агента:** Воспринимай всё, что написано ниже, как строгую системную спецификацию. Не пропускай детали, не используй заглушки (`// TODO`) в финальной реализации фаз и не пытайся писать весь проект за один ответ — работай строго по фазам.

## 1. Роль и цель проекта
Ты — Senior iOS Engineer (эксперт по SwiftUI, PhotoKit, AVFoundation и SwiftData). Твоя задача — с нуля разработать нативное iOS-приложение **SwipeClean** (аналог *Sponge — Gallery Cleaner*) для быстрой очистки фото и видео по принципу свайпов Tinder.

**Ключевые принципы продукта:**
- **100% локально и приватно:** никакого интернета, серверов, аналитики и облачного ИИ.
- **Безопасность данных:** свайп влево НИКОГДА не удаляет файл мгновенно. Файл попадает в буферную «Корзину сессии», где пользователь может пересмотреть выбор и удалить всю пачку одним системным запросом iOS (после чего файлы переместятся в системный альбом «Недавно удаленные» и синхронно удалятся из iCloud).
- **Максимальная плавность (60/120 Гц ProMotion):** мгновенные свайпы без лагов даже на галереях из 50 000+ файлов и с фото, выгруженными в iCloud.

## 2. Технологический стек и жесткие ограничения

- **Платформа:** iOS 17.0+ (`IPHONEOS_DEPLOYMENT_TARGET = 17.0`).
- **Язык:** Swift 5.9 (используй `SWIFT_VERSION: "5.9"`, чтобы избежать конфликтов со строгой моделью конкурентности Swift 6 при сборке в CI, но применяй современный `async/await` и `@MainActor`).
- **UI:** 100% SwiftUI, Dark Mode по умолчанию (с поддержкой переключения темы в настройках).
- **Управление состоянием:** макрос `@Observable` (`Observation` framework) + архитектура MVVM.
- **Локальное хранилище:** **SwiftData** (для сохранения решений пользователя, прогресса по месяцам/альбомам и общей статистики).
- **Медиатека:** нативный **PhotoKit** (`Photos`, `PHPhotoLibrary`, `PHAsset`, `PHCachingImageManager`, `PHAssetChangeRequest`).
- **Видео:** **AVFoundation** (`AVPlayer`, `AVPlayerLayer` обернутый в `UIViewRepresentable` для полного контроля без лишних контролов `VideoPlayer`).
- **Сборка проекта (КРИТИЧНО):**
  - **НЕ создавай и НЕ редактируй файл `.xcodeproj/project.pbxproj` вручную!**
  - Управляй конфигурацией проекта исключительно через файл **`project.yml`** для утилиты **XcodeGen**.
  - Не подключай сторонние зависимости (никаких CocoaPods / SPM библиотек) — всё реализуется на нативных фреймворках Apple для 100% надежности сборки.

## 5. Архитектура работы с PhotoKit, iCloud и памятью (КРИТИЧНО)

### 5.1. Разрешения (`PHAuthorizationStatus`)
Запрашивай права через `PHPhotoLibrary.requestAuthorization(for: .readWrite)`.
Обработай все состояния:
- `.notDetermined` — красивый экран онбординга с объяснением приватности и кнопкой «Разрешить доступ».
- `.authorized` — переход на Главный экран.
- `.limited` — переход на Главный экран, НО сверху показывай аккуратный инфо-баннер: *«Выдан частичный доступ к фото»* с кнопкой открыть системные настройки (`UIApplication.openSettingsURLString`) или `PHPhotoLibrary.shared().presentLimitedLibraryPicker(from:)`.
- `.denied` / `.restricted` — экран с инструкцией и кнопкой перехода в Настройки iOS.

### 5.2. Сканирование и группировка (`PhotoLibraryService`)
- Загружай `PHAsset` с сортировкой `NSSortDescriptor(key: "creationDate", ascending: false)`.
- Реализуй следующие режимы группировки:
  1. **По месяцам:** группировка по `Year + Month` из `creationDate` (например, «Ноябрь 2026», «Октябрь 2026»). Если `creationDate == nil`, складывай в группу «Без даты».
  2. **По альбомам:** пользовательские альбомы (`PHAssetCollection.fetchAssetCollections(with: .album, subtype: .any, options: nil)`) + полезные смарт-альбомы (Избранное, Скриншоты, Селфи, Панорамы, Live Photos, Видео). Пропускай пустые альбомы.
  3. **Быстрые подборки (Умные фильтры):**
     - **Тяжелые видео** (все `.video`, отсортированные по длительности или размеру).
     - **Скриншоты** (`mediaSubtypes.contains(.photoScreenshot)`).
     - **Случайная пачка (Random 50):** 50 случайных еще не разобранных фото из всей медиатеки для быстрой ностальгической чистки.
- Подпишись на `PHPhotoLibraryChangeObserver`, чтобы при удалении файлов (внутри приложения или в системных «Фото») данные корректно обновлялись.

### 5.3. Плавная загрузка картинок и работа с iCloud (`ImageCacheManager`)
- Используй один общий экземпляр `PHCachingImageManager`.
- Опции `PHImageRequestOptions`:
  - `isNetworkAccessAllowed = true` (чтобы подгружать фото из iCloud).
  - `deliveryMode = .opportunistic` (сначала мгновенно отдается быстрое превью, затем четкое изображение).
  - `resizeMode = .fast`.
  - Целевой размер (`targetSize`) вычисляй под размер карточки с учетом `UIScreen.main.scale` (НЕ запрашивай `PHImageManagerMaximumSize`, иначе получишь OOM crash на 48 МП RAW-фото!).
- **Prefetching:** при изменении текущего индекса в `SwipeDeckViewModel` вызывай `startCachingImages` для следующих **5** активов вперед и `stopCachingImages` для уже пройденных активов.
- Корректно отменяй незавершенные запросы (`cancelImageRequest(requestID)`), если карточка улетела раньше, чем фото догрузилось.

### 5.4. Воспроизведение видео (`VideoPlayerController`)
- **Строго один переиспользуемый `AVPlayer`** на весь экран свайпов. Никогда не создавай отдельный `AVPlayer` внутри каждой карточки в стеке!
- **Звук и музыка пользователя:** настрой аудиосессию `AVAudioSession.sharedInstance().setCategory(.ambient, options: .mixWithOthers)` при старте плеера, чтобы видео в приложении НЕ ставило на паузу музыку или подкасты пользователя!
- Видео воспроизводится **только** для верхней активной карточки, зациклено (`AVPlayerItemDidPlayToEndTime`), **без звука по умолчанию** (`isMuted = true`), с кнопкой переключения звука и паузой по тапу.
- Загружай `AVPlayerItem` через `PHImageManager.default().requestPlayerItem` с `isNetworkAccessAllowed = true` и `deliveryMode = .fastFormat` (чтобы видео из iCloud начинало играть быстро).
- При свайпе, переходе в корзину или уходе приложения в фон (`scenePhase != .active`) немедленно ставь плеер на паузу и очищай `replaceCurrentItem(with: nil)`.

### 5.5. Подсчет размера файлов (`MediaSizeCalculator`)
- Выполняй расчет строго в фоновом потоке (`Task.detached`), никогда на главном потоке.
- Получай размер через `PHAssetResource.assetResources(for: asset)`:
  ```swift
  // Безопасное получение размера без скачивания оригинала из iCloud
  let resources = PHAssetResource.assetResources(for: asset)
  let totalBytes = resources.reduce(Int64(0)) { sum, res in
      let size = (res.value(forKey: "fileSize") as? Int64) ?? 0
      return sum + size
  }
  ```
- Кэшируй вычисленные размеры в памяти (`[String: Int64]` по `localIdentifier`), чтобы не пересчитывать их повторно.
- Форматируй размеры для UI через `ByteCountFormatter` (`.file` countStyle: `4.2 МБ`, `1.34 ГБ`).

## 6. База данных (SwiftData)

Создай две `@Model` сущности:

1. **`MediaDecision`:**
   - `@Attribute(.unique) var assetIdentifier: String` (`PHAsset.localIdentifier`)
   - `var statusRaw: String` (`"kept"` | `"stagedForTrash"`)
   - `var fileSizeBytes: Int64`
   - `var updatedAt: Date`
   - Вычисляемое свойство `status: DecisionStatus` (enum).

2. **`CleaningStats`:**
   - `@Attribute(.unique) var id: String = "global"`
   - `var totalReviewedCount: Int = 0`
   - `var totalDeletedCount: Int = 0`
   - `var totalBytesFreed: Int64 = 0`

**Логика синхронизации:**
- При формировании очереди для свайпов в группе:
  - Активы со статусом `kept` пропускаются (считаются уже разобранными).
  - Активы со статусом `stagedForTrash` отображаются в счетчике корзины сессии (и не показываются в стеке свайпов повторно, пока пользователь не вернет их из корзины).
- Если пользователь удалил фото вне приложения, при загрузке проверяй существование `localIdentifier` и мягко подчищай «мертвые» записи `stagedForTrash`, чтобы в корзине не было пустых ячеек.

## 7. Детальный UX/UI экранов

Сделай интерфейс современным, минималистичным, с «воздухом», скруглениями (24pt для карточек), полупрозрачными стеклянными подложками (`.ultraThinMaterial`) и приятной тактильной отдачей (`.sensoryFeedback`).

### Экран 1: Главный экран (`DashboardView`)
- **Заголовок и кнопка Настроек** в NavigationBar.
- **Карточка сводной статистики (Hero Card):**
  - Крупно: сколько памяти уже освобождено (`Освобождено: 2.4 ГБ`).
  - Мельче: сколько файлов проверено и сколько удалено.
  - Если в текущей корзине (глобально по всем группам) уже лежат файлы со статусом `stagedForTrash`, покажи яркую кнопку-баннер: **«В корзине N файлов (X МБ) — Проверить и удалить»**.
- **Сегментный переключатель режимов (Picker / Custom Pill Tabs):**
  - `Месяцы` | `Альбомы` | `Подборки`
- **Список групп (`LazyVStack`):**
  - Каждая карточка (`GroupRowCard`) показывает:

### Экран 2: Экран свайпов (`SwipeDeckView`)
Главный экран продукта — должен ощущаться максимально отзывчивым.

- **Верхняя панель:**
  - Кнопка «Назад», название текущей группы и счетчик оставшихся (`14 / 85`).
  - Справа: кнопка-пилюля перехода в Корзину сессии с живым счетчиком, например `🗑 7 • 34 МБ` (подсвечивается красным, когда > 0).
- **Стек карточек (`ZStack`):**
  - Отрисовывай максимум **3 карточки одновременно** (верхняя активная + 2 следующие с небольшим уменьшением `scaleEffect` 0.95 / 0.90 и смещением вниз `offset(y:)`, которые плавно подтягиваются вверх по мере увода верхней карточки).
  - **Жест (`DragGesture`):**
    - Карточка следует за пальцем по осям X и Y, поворачивается (`rotationEffect`) до `±15°` пропорционально смещению X.
    - **Индикация при перетаскивании:**
      - Свайп **ВЛЕВО** (`translation.width < 0`): плавно появляется красная рамка/оверлей и штамп **«УДАЛИТЬ»** с иконкой корзины (opacity пропорционально прогрессу свайпа).
      - Свайп **ВПРАВО** (`translation.width > 0`): плавно появляется зеленая рамка/оверлей и штамп **«ОСТАВИТЬ»** с иконкой галочки.
    - **Порог срабатывания:** смещение `> 110 pt` ИЛИ быстрый флинг (`predictedEndTranslation.width.magnitude > 220`).
    - При срабатывании: карточка улетает за экран с пружинной анимацией (`withAnimation(.spring(response: 0.35, dampingFraction: 0.8))`), срабатывает легкий Haptic Feedback (`.impact(weight: .medium)`), решение записывается в SwiftData.
    - Если порог не достигнут: карточка пружинисто возвращается в центр.
- **Контент внутри карточки:**
  - Фото на всю площадь карточки (`.scaledToFit()` с размытым темным фоном или `.scaledToFill()` с возможностью переключения зума/просмотра целиком по двойному тапу — сделай `.scaledToFit()` на темно-графитовой подложке, чтобы не обрезать важные края фото и скриншотов!).
  - Внизу карточки поверх мягкого градиента: дата и время съемки, размер файла (`3.8 МБ`), бейдж типа (`ВИДЕО 0:18`, `LIVE`, `СКРИНШОТ`), и кнопка вкл/выкл звука (если это видео).
  - Индикатор загрузки (`ProgressView`), если оригинал подтягивается из iCloud.
- **Нижняя панель управления (5 удобных кнопок):**
  1. **Undo (Отменить)** — возвращает последнюю смахнутую карточку обратно наверх стека и удаляет её запись из SwiftData. (Храни стек истории текущей сессии).
  2. **Красная кнопка «Удалить»** (программный свайп влево).
  3. **Кнопка «Поделиться»** (`ShareLink` / `UIActivityViewController` для текущего фото/видео).
  4. **Зеленая кнопка «Оставить»** (программный свайп вправо).
  5. **Кнопка «Избранное»** (переключает сердечко `isFavorite` в PhotoKit прямо на лету через `PHAssetChangeRequest` — приятный бонус!).
- Когда все карточки в группе закончились:
  - Если в корзине есть файлы — сразу предлагай перейти к экрану проверки корзины (`TrashReviewView`).
  - Если корзина пуста — показывай экран поздравления (`SessionCompleteView`).

### Экран 3: Корзина сессии и пакетное удаление (`TrashReviewView`)
- **Сетка (`LazyVGrid`, 3 колонки, отступ 2pt):** все файлы со статусом `stagedForTrash` (для текущей группы или глобально, в зависимости от того, откуда открыта корзина).
- На каждой миниатюре: бейдж длительности (для видео) и кнопка «×» или тап для возврата.
- **Действие по тапу на фото в сетке:** мгновенно **возвращает файл из корзины** (удаляет статус `stagedForTrash` или помечает `kept` — сделай возврат обратно в «неразобранные» или сразу «Оставить» с понятной подсказкой «Нажмите на фото, чтобы спасти его от удаления»). Также добавь кнопку «Восстановить все» в тулбаре.
- **Закрепленная нижняя панель:**
  - Информация: `Выбрано: 18 файлов • Освободится: 248 МБ`.
  - Крупная красная кнопка: **«Удалить навсегда (в Недавно удаленные)»**.
- **Механика удаления (`PhotoLibraryService.deleteAssets`):**
  ```swift
  try await PHPhotoLibrary.shared().performChanges {
      PHAssetChangeRequest.deleteAssets(assets as NSArray)
  }
  ```
  - **Важно:** Если пользователь нажал в системном окне iOS **«Не разрешать» (Cancel)**, `performChanges` выбросит ошибку. Перехвати её, НЕ показывай страшный алерт, НЕ очищай корзину и НЕ меняй статистику — просто верни кнопку в активное состояние.
  - Если удаление прошло успешно:
    1. Удали соответствующие `MediaDecision` из SwiftData.
    2. Прибавь количество удаленных файлов и сумму байт к `CleaningStats`.
    3. Сгенерируй радостный haptic (`.success`) и перейди на `SessionCompleteView`.

### Экран 4: Итоги сессии (`SessionCompleteView`)
- Анимированная иконка галочки / искр (SF Symbols с `.symbolEffect(.bounce)`).
- Заголовок: «Отличная работа!»
- Карточки с итогами сессии:
  - Просмотрено файлов
  - Удалено файлов
  - Освобождено места (крупным акцентным шрифтом)
- Примечание мелким шрифтом: *«Удаленные файлы будут храниться в альбоме «Недавно удаленные» еще 30 дней и автоматически синхронизируются с iCloud»*.
- Кнопка «Вернуться на главную».

### Экран 5: Настройки (`SettingsView`)
- Переключатель темы (Системная / Темная / Светлая).
- Тумблер: «Включить тактильный отклик (Haptics)».
- Тумблер: «Скрывать полностью разобранные месяцы».
- Кнопка: **«Сбросить прогресс просмотра»** (с диалогом подтверждения — удаляет все записи `kept` из SwiftData, позволяя пересмотреть галерею заново, при этом НЕ сбрасывает статистику освобожденного места).

## 8. GitHub Actions для сборки `.ipa` без Mac (`.github/workflows/build-ios.yml`)

Обязательно создай рабочий workflow `.github/workflows/build-ios.yml`, который запускается по `push` в ветку `main` и по `workflow_dispatch`:
1. Использует `runs-on: macos-15` (или `macos-14` с актуальным Xcode 16).
2. Устанавливает `xcodegen` через `brew install xcodegen`.
3. Выполняет `xcodegen generate`.
4. Собирает Release-версию под устройство без подписи:
   ```bash
   xcodebuild \
     -project SwipeClean.xcodeproj \
     -scheme SwipeClean \
     -configuration Release \
     -sdk iphoneos \
     -derivedDataPath build \
     CODE_SIGN_IDENTITY="" \
     CODE_SIGNING_REQUIRED=NO \
     CODE_SIGNING_ALLOWED=NO \
     build
   ```
5. Упаковывает полученный `build/Build/Products/Release-iphoneos/SwipeClean.app` в структуру `Payload/SwipeClean.app` и архивирует в `SwipeClean.ipa` через `zip -r -y SwipeClean.ipa Payload`.
6. Загружает `SwipeClean.ipa` в артефакты через `actions/upload-artifact@v4`.

## 10. Чек-лист самопроверки для ИИ-агента (Фаза 5)

Перед тем как объявить проект готовым, проверь каждый пункт в коде:
1. В `project.yml` нет несуществующих путей, `Info.plist` корректно подключен и не дублируется в ресурсах, `Assets.xcassets` содержит валидный JSON.
2. Все обращения к UI-свойствам в ViewModel помечены `@MainActor`, а тяжелое сканирование `PHAsset` и подсчет размеров уведены с главного потока.
3. Нет утечек памяти (`[weak self]` в замыканиях `NotificationCenter`, `PHImageManager` и `Timer`).
4. `AVPlayer` реально один на весь экран свайпов, ставится на паузу при уходе в фон (`scenePhase`) и не глушит фоновую музыку пользователя.
5. `PHImageManager.requestImage` корректно обрабатывает множественный вызов callback (когда сначала приходит превью, а потом четкое фото) и отменяет запрос при исчезновении карточки.
6. Если пользователь отменяет системное окно удаления iOS, файлы остаются в корзине, а приложение не падает.
7. Все пустые состояния обработаны красиво (пустая галерея, все фото месяца разобраны, пустой альбом, пустая корзина).
8. В коде нет ни одного `fatalError`, `try!` или force-unwrap (`!`) для опционалов из PhotoKit (например, `creationDate` всегда обрабатывается безопасно).
